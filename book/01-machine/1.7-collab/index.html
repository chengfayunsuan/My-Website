CHAPTER 1.7 代码怎么协作

一个人的时候叫「版本管理」，一群人的时候叫「别互相踩脚」

1.6 章讲的是一个人怎么把程序做出来。这一章讲的是一群人怎么把同一个程序做出来。

这件事听起来只是「多几个人写」，实际上会冒出一堆单干时根本不存在的问题： 你改的文件别人也在改、你想回退但别人已经基于你的改动往上写了、 两个改动分开看都对合在一起就崩、以及——三周后你忘了当初为什么这么改。

解决这些问题的工具叫版本控制，现在几乎只剩一个赢家：Git。 它被用得如此普遍，以至于大多数人只记住了十几条命令， 却从没想过它内部其实只是一个「键值存储 + 几个指针」。 想明白这一点，那些「为什么同一个操作有三种写法」「为什么 reset 会丢东西」 的困惑会一次消掉大半。

这一章就从 Git 的内部结构讲起，然后讲多人改同一个文件会发生什么， 最后讲开源社区是怎么用这套工具协作的。
